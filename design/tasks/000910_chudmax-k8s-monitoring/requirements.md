# Requirements: Chudmax k8s monitoring: Flux, Gateway, and Strata Prometheus stack

> **Public mirror** — the full-fidelity record (including deployment specifics) lives in the private source-of-truth repo.

T-0037 observability card (owner direction, 2026-11-25), adapting `github.com/fluxcd/flux2-monitoring-example` without its bloat: build `k8s/monitoring/` and `.github/workflows/monitoring-validate.yml` in `urmanac/chudmax-mcp` so **Flux repo-sync, the Traefik Gateway API layer, Flagger progressive canaries, and Strata's native Prometheus/vLLM `/metrics`** share one clean, GitOps-reconciled Prometheus contract. The module keeps upstream's proven shape (two-Kustomization split, pinned `kube-prometheus-stack` OCIRepository + HelmRelease, kube-state-metrics customResourceState) and fills three gaps upstream has: source-watcher + flagger scrape coverage, KSM state for `ArtifactGenerator`/`ExternalArtifact`/`Canary`, and LLM-calibrated Flagger metric templates. Upstream's `loki-stack`, `promtail` and `minio` are deliberately omitted (StatefulSet/DaemonSet bloat Chudmax does not need).

## User stories

1. **As the owner**, I want ONE Prometheus contract for the whole stack: Flux sync state, Gateway traffic, canary analysis metrics and Strata's `vllm:*`/`strata:*` LLM telemetry all land in one reconciled stack, with the module split so a platform that already runs a Prometheus/VictoriaMetrics operator installs only the configs.
2. **As the full-stack installer**, I apply `k8s/monitoring/controllers/` then `k8s/monitoring/configs/` and get kube-prometheus-stack (Prometheus + kube-state-metrics; Alertmanager off, Grafana values-gated) plus every Chudmax scrape target, alert, dashboard, NetworkPolicy and Flagger template — reconciled by Flux with drift detection, no credentials and no LAN addresses anywhere.
3. **As a configs-only installer** (e.g. Cozystack, which already runs Prometheus Operator / VictoriaMetrics Operator), I apply `k8s/monitoring/configs/` alone and get all Chudmax scrape targets, alerts, policies and MetricTemplates without duplicating operator CRDs.
4. **As phase 7's canary**, I consume this module's `MetricTemplate`s (calibrated to real LLM slot physics — multi-second decode times, not 500 ms microservice P99s) and its Traefik scrape target, sharing the exact templates with phase 15's `kube-prometheus-stack` placement.
5. **As the operator**, I want alerts that mean something: Flux sources stuck `ready="False"` > 5 m, a canary accumulating failedChecks, and Strata GPU VRAM > 95% / temperature > 83 °C — validated with `promtool check rules`, not hand-hoped.
6. **As CI**, I want `monitoring-validate.yml` to re-prove everything on every push: kustomize builds of both profiles, Flux schema validation, kubeconform strict against k8s + Prometheus Operator + Flagger CRD schemas, promtool rules/PromQL checks, a live Strata mock-engine scrape smoke piped into `promtool check metrics`, and a public-hygiene grep.
7. **As the human**, I want the standing hygiene: box untouched, no registry push, zero RFC1918/LAN IPs (RFC 5737 placeholders only), zero inline credentials (Secret names only), no private repo data, three labels on every claim, conventional commits, the missing-LICENSE flag in the PR description, merge authority CoS.
