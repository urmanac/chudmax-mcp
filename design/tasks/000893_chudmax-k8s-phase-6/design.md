# Design: chudmax k8s phase 6 engine and web charts with umbrella

> **Public mirror** — the full-fidelity record (including deployment specifics) lives in the private source-of-truth repo.

Phase 6 makes three installable chart surfaces and proves them together on kind. The review's major correction changed the architecture: **the fork is public (`github.com/kingdonb/Strata`)** — so the web chart runs real Strata with `--engine mock` (its in-process scripted MockEngine — no dummy mock, no fake server), and the engine-Service rehearsal points at a **mock engine container outside kind on the docker bridge**, rehearsing the exact production topology: **pod → selectorless Service → EndpointSlice → external host** (the docker bridge now, the LAN at phase 11+). Requirements in `requirements.md`; the phase-6 row lives in `kubernetes/phases.md` on the private source-of-truth repo (SPIKE row F); the CoS brief and the Gemini spec review (both 2026-11-25, `handoff-reported`) decided the deltas recorded below.

## Shape (kind rehearsal)

```
 docker host                         chudmax-engine subchart
 ┌─────────────────────────────┐    ┌────────────────────────────────────────┐
 │ docker bridge (kind net)    │    │ Service: no selector, port 8080,       │
 │  ├─ kind node(s)            │    │          targetPort: http (named)      │
 │  │   ├─ web pod: Strata     │    │ EndpointSlice: name http,              │
 │  │   │    --engine mock     │    │                port endpoint.port      │
 │  │   │    (in-process      │    │                address <gateway IP>  ◄─┼──┐
 │  │   │     MockEngine)     │    └────────────────────────────────────────┘  │
 │  │   └─ mcp pod: server    │                                                │
 │  │        (up, no-data) +  │         helm test hook (curl):                 │
 │  │         fetcher waiting │         Service → EndpointSlice → gateway IP   │
 │  └─ Strata --engine mock ◄──┼────────────────────────────────────────────────┘
 │     (the mock engine,       │
 │      OUTSIDE kind, :8080)   │    web hook: web Service /health → 200
 └─────────────────────────────┘      (also proves the allowedHosts default)
```

**Honest framing (printed on the receipt):** the `/health`-through-the-engine-Service proof exercises the Service→EndpointSlice→external-host path against a stand-in Strata on the bridge — the real engine is external and unavailable in CI. Phase 11 supplies the real address as private deployment values and reruns the same hook.

## Key decisions

1. **The fork is public — Strata IS the web image.** The review's correction (verified here: clone @ `de34eba`, tag `v0.2.21-mbp.rtx.1`, MIT): `serve/server.py` defaults `--engine mock`, serves `GET /health`, `GET /mcp`, `POST /v1/chat/completions` (+`/v1/messages`, `/v1/responses`), takes `--mcp-config` (Claude-Desktop JSON) — pure-Python runtime (wheel-only deps; no build tools; the review backed it with `terminal-minimal-server.yml`). This kills the first draft's three assumptions at once: "private until phase 10" (dead), the dummy `/health` `mock_engine.py` (dead — nothing is invented), and the web-without-a-workload rehearsal (dead — the web deploys for real). Phase 7's canary checks (`/health`, `/mcp` tool counts, short chat e2e, selftest questions) run against this same image — nothing thrown away.
2. **The rehearsal topology is the production shape — no hostNetwork.** The mock engine is the same Strata image run **outside kind** on the docker bridge (the kind network) by the smoke script; the EndpointSlice names the bridge **gateway IP** :8080. A pod's path to it — node routing → bridge gateway → published port — mirrors pod→LAN-host in production. The review's reasoning stands: hostNetwork inside kind risks port collisions and same-node kube-proxy hairpin quirks. Recorded alternatives if the gateway route frictions out: the mock container's own bridge IP (still external to the pod network), or a NodePort — each keeps the endpoint EXTERNAL, which is the point being rehearsed. Pod→bridge-gateway reachability: `speculation` until the first run.
3. **Write set narrowed; the charts are in-tree subcharts.** `k8s/umbrella/chudmax/subcharts/` holds the engine and web charts (committed — they are the future phase-10 `urmanac/chudmax-engine`/`-web` charts, vendored until publishing); the mcp chart is consumed by a `file://` reference to the live `k8s/chart/chudmax-mcp` (read-only for phase 6 — no drift possible, no edits allowed while phase 5 is active). `charts/` (the dep-build output) is gitignored. This satisfies "touch only k8s/umbrella/ + umbrella-kind.yml" while keeping all three charts installable as one unit.
4. **Engine endpoint: empty default, TEST-NET-3 in CI.** `engine.endpoint.host` defaults **empty** (supersedes the earlier "bake TEST-NET-1" steering — the review's answer wins): the chart renders the Service only, with NOTES "set this to your engine's address"; CI's engine-address variant uses RFC 5737 `203.0.113.10`; LAN IPs are never committed. Ports are decoupled per the review: Service port 8080 with a **named** `targetPort: http`, EndpointSlice port named `http` with `port: endpoint.port` — the external engine's port can differ from the client-facing port without touching clients.
5. **The web chart = Strata `--engine mock` with the guard configured.** Default image `ghcr.io/urmanac/chudmax/web:0.1.0` (the reference phase 10 publishes; the phase-6/7 builds tag themselves with it so `pullPolicy: IfNotPresent` uses the kind-loaded image — no registry). `STRATA_ALLOWED_HOSTS` comes from the `web.allowedHosts` knob, **default auto**: the rendered in-cluster Service DNS names + `localhost,127.0.0.1` — because the guard 403s unknown Host headers whenever no API key is set (`parse_request`: `host_allowed(host, host_names, "*" in allowed_hosts)`), and an in-cluster curl sends the Service DNS name as Host. The web hook proves the default passes. `*` stays available, documented, discouraged. `web.mcpConfig` is a documented knob (default unset): phase 7 mounts a config registering the in-cluster tickets-mcp Service URL so `/mcp` reports tool counts; phase 6 deliberately does not wire it. The real-engine attach (`--engine strata` / URL) is phase 15's route decision.
6. **Phase 6 ships the Dockerfile Strata lacks.** `web-image/Dockerfile`: `FROM python:3.12-slim`; `pip install -r terminal/requirements.txt` (runtime wheels only — no `requirements-build.txt` tools); non-root uid 65532 (the established pattern); `ENTRYPOINT ["python", "-m", "serve.server"]`; `CMD --engine mock --host 0.0.0.0 --port 8080`. **First non-COPY-only image in this effort:** a pip install cannot cross-compile, so the arm64 leg runs under qemu binfmt **in CI** (the sandbox's binfmt is denied — amd64 built + smoked locally, the arm64 build recorded honestly as CI-only); every runtime dep ships aarch64 wheels (verified from the pin's `requirements.txt`), so nothing compiles. The no-emulation rule bends where the dependency manager forces it — recorded, with docker buildx as the fallback.
7. **No NetworkPolicies in the new charts** — unchanged reasoning from the first draft: CNI-dependent egress guesses were the F5/Cilium trap and the web's constraints wait for phases 12/15. Corrected fact (Fable review): the first draft's "kind's default CNI enforces no policies" claim was **wrong and is retracted** — stock kindnet has enforced NetworkPolicy since kind v0.24 (the smoke pins a current kind, v0.33-era). The rehearsal therefore *does* exercise the mcp chart's enforced policies — which is exactly why the fetcher's reach is asserted from its logs (decision 8), never assumed from pod status. Documented deviation from the mcp chart's pattern.
8. **Rehearsal bar and honest mcp receipts.** Three releases `deployed`; the engine hook passes `/health` through the Service (bridge Strata); the web hook passes (guard-proof); the mcp pod Running with the server answering 200 (initialize) and the honest no-data body; the fetcher waiting for the ExternalArtifact is **expected** (4b's startup fix) — but a *waiting* fetcher and a *policy-blocked* one look identical on pod status, so the smoke **asserts the fetcher's logs show a real API-server round-trip**: the ExternalArtifact `Get`'s **404 NotFound** ("does not exist yet, waiting") — that line can only appear if kube-apiserver answered, proving the enforced NetworkPolicy's apiserver rule on stock kind (an RBAC denial would log 403, not 404; a blocked route logs neither). The commit→tickets data-path proof is phase 5's — not duplicated (steering).
9. **Toolchain and pins.** Images build under podman → `podman save` → `kind load image-archive` — no registry. The smoke script clones Strata at the SHA recorded in the README pins table (+ the workflow env) — a moving main never silently changes the image. Local kind = docker provider; CI kind on `ubuntu-latest` = well-precedented, `speculation` until green.
10. **Parallel-safety and phase-5 coordination.** The phase-6 file set is disjoint from phase 5's; helpers duplicated not shared; branch off current `main`; phase 5's branch never a dependency; its spec (`design/tasks/000903_chudmax-k8s-phase-5-sync`) consulted for adoptable scaffolding, copied not referenced. Coordination on the mcp chart (read-only for phase 6): phase 5 is changing `apiServer.mode`'s default to **auto** (`.Capabilities.APIVersions.Has "cilium.io/v2/CiliumNetworkPolicy"` → a CiliumNetworkPolicy only where the CRDs exist); the umbrella installs with the mcp chart's defaults untouched, **rebases onto `main` before the final CI run** so its `file://` dep carries the gate, and its kind proof asserts **no Cilium CRDs render on stock kind** (kubeconform's default k8s schemas double as the tripwire).

## Implementation notes (2026-11-25, implementation session)

- **Toolchain installed in the fresh sandbox:** podman 5.4.2, helm 3.16.4, kubeconform 0.6.7 (the **yannh** release — the org the repo's CI uses; `kubernetes-sigs` 404s), kind upgraded v0.27.0 → **v0.33.0** (phase 5's pin, verified real); docker daemon runs in-sandbox → kind on the docker provider works. The phase-3 recipe held (helm tarball from get.helm.sh; gotcha: `tar -C /usr/local --strip-components=1` puts the binary at `/usr/local/helm` — move it into `/usr/local/bin`).
- **Phase 5's spec landed** (`000903_chudmax-k8s-phase-5-sync`) mid-setup — read in full (`verified-here`). Confirmed disjoint sets: phase 5 owns `k8s/chart/chudmax-mcp/` edits (apiServer.mode auto + ports 443/6443, the bearer-aware server readinessProbe, the source-watcher label fix), `k8s/tickets-mcp/` (bind-once docs fix), `k8s/repo-sync/artifact-ingress.yaml`, `k8s/rehearsal/**` + `.github/workflows/rehearsal-sync.yml` — touching nothing of mine; its decision 8's "phase 6 owns umbrella.yml and the engine-chart/web-chart dirs" is the stale pre-review layout — my review-corrected set (`k8s/umbrella/**` + `umbrella-kind.yml`, subcharts inside) stays disjoint either way.
- **Adopted-by-copy from phase 5** (allowed, no dependency): the `kubectl get endpoints kubernetes` → `apiServer.mode: cidr` discovery trick — my kind-smoke tries the mcp chart's DEFAULTS first and only if the fetcher's 404-log assertion fails applies the same cidr override from the umbrella's rehearsal values (the auto fallback's ipBlock/service-CIDR match under kindnet's post-DNAT evaluation is exactly the open empirical question the assertion answers); their amd64-only rehearsal-load decision; their `docker/podman save → kind load image-archive` mechanics.
- **Strata pin receipt (`verified-here`, clone @ `de34ebaa521d8f628b4bb1884e5c34101730299a`, tag `v0.2.21-mbp.rtx.1`):** `MockEngine` is a class in `server.py` (L471) — the mock engine is self-contained; `ROOT = parents[1]` = `terminal/` and nothing outside `terminal/` is imported (no `tools`/`engine`/repo-root imports; the `sys.path` inserts are no-ops) — so the image COPYs only `terminal/`; `host_names` defaults to `LOOPBACK_NAMES` (L4254) and `host_names_for()` folds in the bind host + hostname — in-cluster Service-DNS calls genuinely need `STRATA_ALLOWED_HOSTS` (the knob is load-bearing, not decorative); the tree is 208M but `terminal/` alone is what the image carries.
- **kind cannot run in this sandbox — a hard constraint, discovered at the first smoke attempt:** the docker daemon is ROOTLESS (SecurityOptions: rootless), PID 1 is `startup.sh` (no systemd), and cgroup2 is mounted read-only — kind v0.33.0 refuses verbatim: `failed to create cluster: running kind with rootless provider requires setting systemd property "Delegate=yes"` (the teardown trap fired cleanly). No provider escape exists (podman rootless hits the same delegation requirement; a nested rootful dockerd cannot create cgroups under the ro mount). **Decision: the kind job in CI is the authoritative receipt** (GitHub's rootful runners; kind v0.33.0 pinned there) — the phase-5 precedent ("podman best-effort; CI authoritative") applied verbatim. The `kind-smoke.sh` rungs that need a cluster (hooks, mcp receipts, the fetcher-log assertion, the endpoint-route ladder) are therefore `speculation`-labeled until the first green CI run.
- **What the sandbox COULD run (`verified-here`):** all three images build under podman — web 262MB (the pip install pulls runtime wheels only; the `pip 25.0.1 → 26.3` notice and the rootless "not a shared mount" warning are harmless), fetcher 36.7MB, tickets-mcp 51.2MB; `podman save --format docker-archive` → `docker load` interop proven (the archive format `kind load image-archive` consumes); the mock engine runs standalone and answers `/health` 200 — **including `Host: chudmax-engine:8080` (the short-name+port case an in-cluster hook actually sends) — while a foreign Host 403s**, `GET /mcp` 200, and `POST /v1/chat/completions` returns the scripted "Hello from the mock engine." turn.
- **The guard's short-name lesson (a real fix this phase):** Strata's `host_name()` strips the port and lowercases ("Example.com:8080" → "example.com"), but a same-namespace curl sends the SHORT service name as Host — the FQDN-only auto list would 403 it. The `allowedHosts` auto default now renders **short, mid and FQDN Service names + loopback**; proven live by the Host-header curls above.
- **The canonical server's HTTP surface:** `do_POST` is path-agnostic (any path; one JSON object per POST, 202/405/400 semantics intact) — the rehearsal's initialize/list_tickets probes POST to `/mcp`; `do_GET` answers 405 with "POST a JSON-RPC request to /mcp".
- **Helm file:// gotcha:** dependency `repository:` paths resolve relative to the CHART directory — the mcp chart is **two** ups (`../../chart/chudmax-mcp`), not three; the first dep build failed with "directory chart/chudmax-mcp not found" until corrected (the spec docs fixed too).
- **Actions YAML gotcha:** an unquoted step `name:` containing `: ` breaks the parse ("mapping values are not allowed here") — quote such names.
- **Umbrella render shape (`verified-here`):** defaults render 2 Deployments (web+mcp), 2 NetworkPolicies (the mcp pair), 2 hook Pods, Role/RoleBinding/SA, 3 Services — no EndpointSlice, **no Cilium** (the auto fallback renders plain); the `203.0.113.10` variant adds the EndpointSlice; kubeconform -strict clean on all renders.

## Implementation notes — the CI loop (2026-11-25, continued)

- **CI on PR #6:** every job but `kind` green from the first run (chart proofs, web-image both arches, and the repo's other workflows); the `kind` rehearsal is iterating — the full failure history with receipts lives in proofs.md (`CI iteration history`). The read-path that works anonymously: the **run-summary page** renders the step-summary tail (the workflow writes the log tail there on failure); the annotations dialog needs sign-in and the REST API rate-limits the sandbox's shared IP.
- **The Host-guard mask (the phase's most instructive bug):** Strata's DNS-rebinding guard 403s unknown Host headers — so ANY probe that curls the mock by IP literal (the bridge gateway, the container IP) looks "unreachable" while the network is fine. A probe against this mock must carry `Host: chudmax-engine` (the Service's short name — what a same-namespace client sends and what the Service's DNAT preserves). This masks BOTH directions: in a probe ladder and in any hand-run debugging. The same lesson already shaped the chart (allowedHosts auto renders short+mid+FQDN names).
- **The hygiene grep covers scripts too:** the LAN-address tripwire matches ANY file under `k8s/umbrella/**` — a runtime fallback literal (docker's bridge gateway) in `kind-smoke.sh` failed the chart job. Rule: no dotted-quad RFC1918 literals anywhere in the phase-6 tree; compute at runtime or die with diagnostics.
- **`kind load image-archive` loads the node's containerd store only** — a mock engine run via `docker run` on the host needs `docker load` from the same archive (both loads per archive is the pattern).
- **`docker network inspect kind` may list the IPv6 IPAM block first** — grep for an IPv4-shaped gateway (`"Gateway": "[0-9.]*"`), and never fall back to a hardcoded RFC1918 literal (see above).

## Notes for future agents (learnings)

- **What the review killed from the first drafts (do not resurrect):** the "fork is private until phase 10" assumption (it is public NOW); the dummy `/health` `mock_engine.py` stand-in (use real Strata `--engine mock` everywhere a mock engine is needed); the hostNetwork-in-kind endpoint (use the docker-bridge gateway); the baked TEST-NET-1 endpoint default (empty + RFC 5737 in CI templates); the `k8s/engine-chart/`/`k8s/web-chart/` top-level dirs (the charts are subcharts under `k8s/umbrella/chudmax/subcharts/`); the separate `umbrella.yml` name (it is `umbrella-kind.yml`).
- **Strata facts (clone @ `de34eba`, MIT — `verified-here`):** `--engine` defaults `mock` (server.py:9218); `--host` (9221), `--mcp-config` Claude-Desktop JSON (9268); `GET /health` (7660), `GET /mcp` (7640), `/v1/mcp/tools` (7645), `/v1/mcp/call` (7835), `POST /v1/chat/completions` (7923); the Host guard: without an API key, EVERY request passes `host_allowed` first — unknown Host → 403 naming `STRATA_ALLOWED_HOSTS` (~7175–7206; env read at 9667). The review cited L6558 on its pin — **line numbers drift between pins; verify the mechanism, cite the pin**. Runtime requirements are wheel-only pure-Python (numpy/jinja2/pillow/psutil/requests/pyyaml/regex/tqdm); `requirements-build.txt` (CMake/Ninja) is for local builds only. **No Dockerfile in-tree** — phase 6 ships `web-image/Dockerfile`.
- **Kind-load trick:** build images TAGGED with their chart-default references (`ghcr.io/urmanac/chudmax/web:0.1.0`, `…/fetcher:0.1.0`, `…/tickets-mcp:0.1.0`) — `pullPolicy: IfNotPresent` then uses the loaded images with no values overrides and no registry.
- **kindnet enforces NetworkPolicy (Fable correction — do not repeat the first draft's error):** since kind v0.24 the stock CNI enforces policies; the smoke pins a current kind, so kind proofs exercise real NetworkPolicy behavior. Consequence: a blocked pod and a waiting pod look the same — **assert on logs** (the fetcher's apiserver-404 line), never on pod status alone; 404 = reached the apiserver, 403 = reached-but-denied (RBAC), neither = blocked in flight.
- **Bridge mechanics for the smoke script:** the mock engine joins kind's docker network; the gateway IP resolves via `docker network inspect`; the container publishes :8080. Alternatives recorded in decision 2 if pod→gateway frictions out — the endpoint must stay EXTERNAL (that is what is being rehearsed).
- **Sandbox facts:** docker/kind/kubectl present; podman/helm per the phase-3 recipe; binfmt denied (arm64 *builds* CI-only this phase — the phase-3 host-qemu-exec trick does not transfer to a pip-installed venv); the box unreachable (curl exit 7).
- **Chart-pattern sources (patterns, not text):** `k8s/chart/chudmax-mcp/` — values style, unpublished-tag wording, pod-level securityContext, kubeconform-on-rendered CI, NOTES conventions, installer-facing values tables.
- **Labels vocabulary** (`chudmax/AGENTS.md`): `verified-here` / `handoff-reported` / `speculation` (kind-in-CI, pod→bridge-gateway, the auto allowedHosts default's real-world fit).
- **Docs rule:** this branch and the code repos are public — the engine's real LAN address, credentials, and internal proxy hostnames never appear; the card's literal address is deliberately absent from these docs.
- **Debugging a Strata-fronted endpoint from a pod: always set the Host header explicitly.** 403 from the guard looks like a network block in every ladder/probe construction; `curl -H 'Host: <service-name>' http://<ip>:<port>/health` is the correct probe shape (the Service's DNAT preserves the client's Host, so this is also the faithful rehearsal of the real path).
- **`kubectl run --rm -i` loses fast containers' stdout (the attach race):** curl answers in milliseconds — refused, 403, or 200 alike — and exits before the attach stream opens; the output is lost and EVERY probe reads as empty, successes included. Never read a one-shot container's result from the attach stream: create the pod without -i, wait for completion, then `kubectl logs`. (Three CI runs were diagnosed blind by this.) Also: a diagnostic `echo` inside a function called under `$( )` is captured, not printed — diagnostics go to STDERR.
- **Assert CRD shapes, not words:** the read-only mcp chart's templates carry "Cilium" inside explanatory YAML comments that render verbatim; a bare `grep -qi cilium` on a full umbrella render is a false positive. `grep -E 'kind: *CiliumNetworkPolicy|apiVersion: *cilium\.io/'` is the assertion.
- **Two helm alias-label facts (learned on kind):** (1) inside an aliased subchart, `.Chart.Name` renders the ALIAS — pod labels read `app.kubernetes.io/name: mcp` while the fullnames read `chudmax-mcp` (from `fullnameOverride`) — select pods by the alias label, address objects by their names; (2) **a Service admits only READY pods** — the mcp pod is intentionally not-Ready pre-artifact (the fetcher's `test -e /data/current` readiness probe is the honest no-data state), so the mcp Service has no endpoints in a rehearsal that never ships an artifact; probe the POD IP (the ingress policy's same-namespace `podSelector: {}` admits it) and record the empty endpoint set — the ready-gated Service path belongs to the rehearsal that DOES ship an artifact (phase 5's).
- **`curl -s` hides failures from pod logs:** without `-w` a failed curl prints NOTHING to stdout (errors are stderr and silenced by -s) — pod logs then read empty. Use `-sS` (error line → stderr → kubectl logs merges it) plus a `-w '%{http_code}'` for code-only probes.
- **A NetworkPolicy upgrade restarts nothing:** any assertion that follows a policy change must either poll patiently past the workload's own retry cadence (the fetcher's resync is 1m) or restart the deployment (its first dial fires immediately — the fast, deterministic choice).
- **controller-runtime needs the CRD served, not just the RBAC:** on a cluster without the Flux source-controller CRDs, the fetcher's Get fails at DISCOVERY (`no matches for source.toolkit.fluxcd.io/v1`) — which is NOT IsNotFound — so a "wait for the 404" assertion can never pass. The rehearsal ships a minimal, schemaless CRD as a mapping fixture (no controller — phase 5's rehearsal owns the artifact flow).
- **kindnet's DNAT stage is unknown by design:** admit BOTH the kubernetes Service VIP (443 — the pre-DNAT dial from the in-cluster config) and the control-plane endpoint (443+6443 — the post-DNAT path) in a rehearsal override; after phase 5's chart fix (the 443+6443 selector rule) the defaults may admit it themselves — the smoke re-checks the defaults first on every run.

## What this settles

- The pointer chart, the REAL web chart (Strata with its mock engine), and the umbrella exist as reviewable, installable units — and the image phase 7's canary needs already exists at a recorded pin.
- The rehearsal topology is the production topology (external endpoint through a selectorless Service), so phase 11's real run changes exactly one value.
- Still `speculation` after this spec: kind-in-CI reliability, pod→bridge-gateway routing, the auto allowedHosts default against Strata's real guard — first exercised in the implementation run, re-labeled from evidence.
