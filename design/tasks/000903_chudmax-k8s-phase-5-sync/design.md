# Design: chudmax k8s phase 5 CI sync rehearsal

> **Public mirror** — the full-fidelity record (including deployment specifics) lives in the private source-of-truth repo.

Phase 5 is the first phase with a cluster: a throwaway kind cluster inside a CI job on a GitHub-hosted runner (settled policy — no gate), Flux installed into it, the chart installed with **default values** (fetcher + the REAL published canonical server), the repo-sync test manifests applied, **Cilium** enforcing NetworkPolicies, and the card's two proofs run to completion with nothing touched by hand. Two review rounds (Gemini, then Fable) are folded in BEFORE implementation — without their fixes the rehearsal cannot even start: the CRD rejects the old test URL, the broken apiserver rule blocks the fetcher's watch under Cilium, and an unconditional CNP render would break phase 6's stock-kind install. Requirements are in `requirements.md` in this directory.

## Shape

```
CI job (GitHub-hosted ubuntu runner — settled policy, no privileged machinery needed)
  /srv/git/repo.git + Smart HTTP test server on the runner:
      tiny Go helper wrapping fluxcd/pkg/gittestserver (separate module under k8s/rehearsal/)
      → http://<gateway-ip>:<port>/repo.git   [passes the CRD's ^(http|https|ssh):// pattern]
      [pre-flight: git ls-remote proves the URL BEFORE the manifest is applied]
  kind create cluster (kindnet would enforce policies too — Cilium chosen for
      Cozystack parity + CiliumNetworkPolicy coverage) --policy-cidr-match-mode=nodes
  flux install -v v2.10.1 --components-extra=source-watcher   (shipped policies ON)
  build fetcher + server images (docker) → save → kind load image-archive   [no registry]
  helm install chudmax-mcp k8s/chart/chudmax-mcp   (default values — the REAL server;
      apiServer.mode: auto → the cluster HAS Cilium → CiliumNetworkPolicy toEntities: [kube-apiserver])
      → fetcher WAITS (Running, not-ready, no crash-loop — the phase-4b behavior, for real)
      → server READY via its new bearer-aware readinessProbe even before data arrives
  apply: gitrepository-test.yaml + artifactgenerator.yaml + artifact-ingress.yaml (from k8s/repo-sync/)
  git push #1 → chain delivers v1 hands-off → push #2 → v2 served, NO restart
             → push #3 → retention prunes → the server still answers
  helm upgrade --set apiServer.mode=cidr --set cidrs=<discovered>   (policy-only)
      → FRESH in-pod API GET succeeds (an established stream proves nothing)
      → push #4 → delivered hands-off under the upgraded policy; no pod restart
  denials: rogue pod → RBAC 403 + tarball GET denied; controls prove the fences bite
  kind delete cluster (always)

  http://<gw>:<port>/repo.git ──► GitRepository (interval 1m, no secretRef)
        │  source-controller (flux-system; unrestricted egress)
        ▼
  ArtifactGenerator (copy rules: the four narrowed entries) ──► ExternalArtifact chudmax-tickets
        │  get+watch — the phase-3 Role, resourceName-pinned; watch needs the FIXED apiserver rule
        ▼
  fetcher ──GET :9090──► source-watcher storage ◄── k8s/repo-sync/artifact-ingress.yaml ADMITS
        │  unpack, swap /data/current                             the release's pods
        ▼
  server (the published canonical tickets-mcp, bearer-aware readiness-probed)
      — list_tickets over the Service: the answer
```

## The review fixes folded in

**Round 1 — Gemini spec review (2026-11-25):**

- **The test repo is Smart HTTP, not git://** (`verified-here` against upstream `api/v1/gitrepository_types.go` v1.10.2: `+kubebuilder:validation:Pattern="^(http|https|ssh)://.*$"` on `spec.url` — the CRD rejects `git://` at kubectl apply / flux-schema, before go-git ever runs). **Round 2 — Fable** replaced the wrapper: NOT Python's `CGIHTTPRequestHandler` (removed in Python 3.15) — the runner serves the bare repo via **a tiny Go helper wrapping Flux's own `fluxcd/pkg/gittestserver`** (battle-tested by Flux's CI; smart HTTP; bearer/auth knobs we don't need). It lives in a **separate module under `k8s/rehearsal/`** — the fetcher module's dependency set stays untouched (its go.sum must not grow for a rehearsal-only tool). Documented fallback: a Python `BaseHTTPRequestHandler` driving `git-http-backend` via subprocess. Zero secrets, zero remote pushes — the workflow needs no push token at all.
- **The kube-apiserver egress rule is an F5 regression, fixed here** (current rule: `podSelector {component: kube-apiserver}` on TCP 443 — `verified-here`; semantics `handoff-reported` — Gemini; the Cilium run receipts both): NetworkPolicy evaluates **post-DNAT backend ports** (the apiserver listens on **6443**, not the Service's 443), and the apiserver is a **`hostNetwork: true` static pod** — a podSelector-based rule resolves to an **empty set** under Cilium/Calico, so the fetcher's watch is blocked immediately. Fix in the chart (`values.yaml` + `templates/networkpolicy-egress.yaml`):
  - the apiserver rule allows TCP **443 and 6443** in every mode;
  - **`apiServer.mode: auto` is the new default** (Fable): the CiliumNetworkPolicy (`toEntities: [kube-apiserver]`) renders ONLY when `.Capabilities.APIVersions.Has "cilium.io/v2/CiliumNetworkPolicy"`; without the CRDs the standard ipBlock fallback renders (ports 443+6443) — so **phase 6's stock-kind install with chart defaults cannot fail on a missing CRD**; `helm template` (no cluster) always renders the fallback, which keeps CI's plain validation honest;
  - explicit **`cilium`** and **`cidr`** modes kept for CI/overrides (`cidr`: the ipBlock list of control-plane endpoint IPs — values-driven, discovered in `rehearse.sh` via `kubectl get endpoints kubernetes`);
  - the `podSelector` mode kept with its hostNetwork limitation documented (legacy, non-hostNetwork platforms only);
  - values comment + chart README updated; the chart CI's schema check handles the CNP render (the Cilium CRD schema fetched in the validation job) and the fallback render validates plain.
- **The server readinessProbe (architecture.md's list_tickets probe).** The server container has no readiness probe today and `GET /mcp` is a 405 — the probe must speak the protocol: an **exec** probe POSTing `list_tickets` (or `initialize`) to `127.0.0.1:<server.port>/mcp` with `python3 -c`, asserting HTTP 200. **Bearer-aware (Fable):** when `server.auth.enabled`, the probe reads `/var/run/mcp-auth/token` and sends `Authorization: Bearer <token>` — a headerless POST would 401 and the pod would never go ready; the auth-enabled variant is rendered and schema-checked in CI. Semantics: the probe tolerates the pre-data state (the tools answer honestly without a tree — the 4b contract), so it proves the MCP surface is alive (it would have caught the `--host` misbind the 4b smoke caught); the fetcher's `test -e current` probe still gates the POD's readiness until the first swap.
- **The published server's docs-methods single-snapshot bug** (`verified-here` — published copy `ticket_mcp.py` L355–410). `list_docs`, `read_doc`, `search_docs` re-resolve the base repeatedly (in `readable()` and again in their loops), so a symlink swap mid-call can raise an unhandled `ValueError` or falsely refuse; `repo_facts` already binds once — the docs methods were missed. Fix: bind `base = self.base()` ONCE at the start of each method and pass it into `readable(base)`; the published selftest gains a regression check (a concurrent swap during docs calls never raises, never falsely refuses — either-tree answers are valid, crashes are not). **Byte-exactness is preserved the 4b way:** the identical fix + test go to the canonical via the private GitLab MR (held for the human; the public PR does not wait on it; a session without provider access flags that honestly instead of diverging silently). Plus the stale mock comment in `k8s/image/Dockerfile` L2–3 corrected to the published canonical.
- **Rehearsal-check refinements:** (a) `repo_facts.origin_revision` is asserted to **contain** the pushed commit SHA — the exact string (e.g. `main@sha1:<sha>`, the generator's fallback per the 4b finding) is recorded from source-watcher v2.3.1's LIVE output rather than assumed; (b) the rehearsal verifies live whether notification-controller matches `kind: ArtifactGenerator` events — if not, `eventSources` gains `ExternalArtifact` and the README records the finding; the delivered-event assertion to the dummy sink stays optional.

**Round 2 — Fable's five fixes on the revised spec:**

1. **No Cilium CRD collision** — the `auto` default + APIVersions gate above (this is the fix that keeps phase 6 working).
2. **The cidr-mode check is honest:** Cilium's ipBlock ignores node IPs unless `--policy-cidr-match-mode=nodes` — **rehearse.sh installs Cilium with that flag** (harmless for the other checks, honest for cidr). And "watch stays connected" after the upgrade proves nothing — **an established TCP stream can survive a policy change** — so the post-upgrade verification forces a FRESH connection: a fresh in-pod API GET succeeds (direct apiserver-path check) AND a **fourth commit** is delivered hands-off end-to-end under the upgraded policy (the whole chain re-proven, fresh connections included), with the policy-only-upgrade **no-pod-restart** assertion kept. The README documents cidr's Cilium caveat (nodes-match-mode, or non-Cilium).
3. **The bearer-aware probe** (above).
4. **`artifact-ingress.yaml` moves from `k8s/rehearsal/` to `k8s/repo-sync/`** — any cluster running Flux's shipped policies needs the :9090 ingress allowance into flux-system, not just the CI rehearsal. The manifest lands there (no `metadata.namespace` — the repo-sync install convention), the repo-sync README documents when it is needed, the existing repo-sync schema validation covers it, and `rehearse.sh` applies it from there. The phase-12 note stays in a comment (real-platform prerequisite, or place the release in flux-system).
5. **The gittestserver helper** (above) and **the kindnet correction:** kindnet has **enforced NetworkPolicy since kind v0.24** (we pin v0.33) — the denial proof is non-vacuous under either CNI; **Cilium is chosen for Cozystack parity and CiliumNetworkPolicy coverage** (the `toEntities: [kube-apiserver]` rule is Cilium-only), not because kindnet lacks enforcement.

## The three-commit recipe (Fable's, owner-endorsed) — plus the fourth

- **Commit #1** is pushed before the repo-sync manifests apply, so the FIRST reconciliation is itself the delivery event (the fetcher's wait → self-heal → swap is observable). After it: `list_tickets` shows the seed ticket; `repo_facts` captured.
- **Commit #2** is the Fable regression under real API load: the probe polls `list_tickets` continuously across the swap window; once v2 appears, no answer ever serves the stale v1 tree again; the server container's `startedAt` and `restartCount` are unchanged.
- **Commit #3** drives retention: the default `--keep 3` prunes the first revision dir on the third swap (`verified-here`, `k8s/fetcher/main.go`); after the prune the server still answers — the reread survives pruning.
- **Commit #4** (after the cidr-mode upgrade) re-proves the whole chain hands-off under the upgraded policy — the fresh-connection evidence Fable's fix 2 demands.
- **`repo_facts` between every pair of commits**, asserted and recorded; all JSONs go to the CI step summary — phase 4's "records exactly what `repo_facts` surfaces" promise is kept.

## The three integration facts (why the rehearsal exists)

**1. The chart's egress selector points at labels the pods do not carry.** Default `networkPolicy.egress.sourceController.selector` is `app.kubernetes.io/name: source-watcher`; the pinned v2.10.1 bundle puts `app: source-watcher` (+ `app.kubernetes.io/component`) on the pods — `verified-here` (bundle fetched and grepped, 2026-11-25). Phase 4b's F4 scoping was right; the label was never checkable without a cluster. Phase 5 owns the one-line fix; without it the fetcher's GET has no egress allowance.

**2. Flux's own shipped policies deny the cross-namespace fetch.** `allow-egress` selects every flux-system pod with same-namespace-only ingress; the only cross-namespace openings are :8080 and notification's :9292 — `verified-here`. Storage is :9090, so the ingress allowance (now in `k8s/repo-sync/artifact-ingress.yaml`) adds the additive allow: ingress :9090 to `app: source-watcher` pods from the release namespace's release-labeled pods. The rogue pod is denied by BOTH fences; the fetcher is admitted by exactly the allowance; the label-carrying Role-less control pod proves the admission shape is what opens the path.

**3. The apiserver egress rule cannot match the real apiserver** — the F5 regression above; the `auto`/`cilium`/`cidr` fix and the both-modes live proof are this phase's deliverable.

## The proofs (the script's check sequence)

1. **Pre-flight (runner-side, before the cluster):** the gittestserver helper is built, the Smart-HTTP server is up, and `git ls-remote` proves the rendered URL — the receipt that the CRD-valid `http://` route works before anything is applied.
2. **Fresh install:** chart applied before the repo-sync manifests — pod Running, fetcher not-ready (waiting, not crash-looping), restartCount 0; the server container READY via its new probe even before data arrives; the rendered apiserver rule is the CNP (auto resolved on a Cilium cluster).
3. **v1 arrives:** manifests applied → ExternalArtifact generated → the fetcher self-heals → pod ready → probe pod POSTs `list_tickets` over the Service → the seed ticket is in the answer.
4. **Commit #2:** continuous `list_tickets` polling across the swap; v2 served; no stale answer after the swap; `startedAt`/`restartCount` unchanged.
5. **Commit #3:** retention pruned (`/data/revisions` ≤ 3, v1's dir gone), the server still answers; the three `repo_facts` JSONs recorded (shapes asserted per the round-1 refinement).
6. **Denial (RBAC):** rogue pod (release ns, default SA, no labels) GETs the ExternalArtifact through the API → 403 — it cannot even learn the artifact URL (the Role is resourceName-pinned; phase 4's answer, now proven).
7. **Denial (network, Cilium-enforced):** the same rogue pod GETs `http://source-watcher.flux-system.svc:9090/<artifact path>` → denied, while (a) the fetcher's GET succeeds under the chart's egress policy (DNS 53, the FIXED apiserver rule, source-watcher :9090) and (b) a label-carrying, Role-less pod CAN GET the tarball. Port-scope probe from inside the chudmax pod: :9090 allowed, an unlisted port (e.g. :8080) denied.
8. **Policy-only upgrade + fresh connections:** `helm upgrade` to `apiServer.mode: cidr` (endpoint IPs discovered via `kubectl get endpoints kubernetes`) → fresh in-pod API GET succeeds (the established-stream caveat honored) → commit #4 delivered hands-off end-to-end → no pod restart from the policy-only upgrade.
9. **The record:** `repo_facts` JSONs, the artifact URL (host:port shape — `source-watcher.flux-system.svc…:9090`, trailing dot as advertised), the live `origin_revision` strings, and probe outputs go to the step summary; on failure the job uploads logs + `kind export logs`.

Timing budget: kind + Cilium ≈ 4 min, flux install ≈ 1 min, images + archive-load ≈ 3 min, four commits × ≤ ~1.5 min ≈ 6 min, denials + mode upgrade ≈ 3 min → ~17 min expected; `timeout-minutes: 45`.

## Key decisions

1. **GitHub-hosted runners run kind — settled policy.** The 2025-era "privileged GitLab runners or self-hosted k3d" flag is obsolete (CI moved to GitHub Actions); not flagged anywhere in this card's outputs. The first green rehearsal run is the standing receipt.
2. **Cilium is the CNI — for Cozystack parity and CiliumNetworkPolicy coverage**, NOT because kindnet lacks enforcement (kindnet enforces since kind v0.24; we pin v0.33 — Fable's correction). The `toEntities: [kube-apiserver]` rule is Cilium-only, which is exactly the coverage the apiserver fix needs.
3. **`apiServer.mode: auto` is the chart default** with the APIVersions gate and the ipBlock fallback — the chart must install cleanly with defaults on stock kind (phase 6) AND resolve to the CNP on Cilium clusters; explicit `cilium`/`cidr` remain for overrides; `podSelector` is legacy with a documented limitation. A loud, documented shape beats either a broken default or a CRD-colliding one.
4. **Smart HTTP via Flux's `gittestserver` is the test-repo route** (the CRD-pattern finding corrected the steering's git-daemon instinct; Fable replaced the deprecated Python wrapper); separate Go module so the fetcher module stays lean; `git ls-remote` pre-flight receipt; no push token in the workflow.
5. **The REAL server via chart defaults** — no stand-in; images loaded via archive (`docker/podman save` → `kind load image-archive`), never pulled (the default ghcr tags stay unpublished until phase 10). amd64 only in the rehearsal job — both-arches is already proven by the image jobs; the rehearsal proves the chain, not the manifest list.
6. **Flux's shipped policies stay ON** (realistic); the :9090 ingress allowance is a first-class `k8s/repo-sync/` file (Fable) — rehearsal-owned behavior removed; `flux install --network-policy=false` is documented as the escape hatch only.
7. **Pins:** flux v2.10.1 (`--components-extra=source-watcher` — the same family phase 4's CI pinned), kind v0.33.0 (current stable, docs fetched 2026-11-25), Cilium pinned (CLI install + `--policy-cidr-match-mode=nodes`), `fluxcd/pkg` pinned in the helper module, probe images pinned by tag/digest.
8. **Workflow boundary:** `.github/workflows/rehearsal-sync.yml` is this card's only workflow file; phase 6 owns `umbrella.yml` and the engine-chart/web-chart/umbrella dirs — this card edits none of them and duplicates any helper it needs into `k8s/rehearsal/`.
9. **Receiver untested in-cluster** (inert without an ingress path by design); **Alerts applied with the dummy sink** but the delivery assertion optional (the round-1 refinement).
10. **The server fix keeps the canonical byte-exact via the parallel private MR** (the 4b pattern: the canonical defines the contract; the public PR does not wait on the human's merge).

## Notes for future agents (learnings)

- **Settled (do not resurrect):** the CI capability question is closed policy — GitHub-hosted `ubuntu-latest` runners run kind natively; the spike's "privileged GitLab runners or self-hosted k3d" flag predates the GitHub move and must not be re-flagged in any spec, PR, or doc — `handoff-reported` (CoS, 2026-11-25).
- **GitRepository.spec.url is CRD-pattern-validated** `^(http|https|ssh)://.*$` (source-controller `api/v1/gitrepository_types.go`, checked at v1.10.2) — `git://` and any other scheme die at the API server, before go-git. Any "git-daemon serves the test repo" idea is dead on arrival; the local-test-repo route is Smart HTTP — `verified-here` (2026-11-25).
- **Never render a CRD-gated manifest unconditionally in a shared chart:** gate on `.Capabilities.APIVersions.Has "<group>/<version>[/<kind>]"` with a plain-K8s fallback (Fable's fix; phase 6's stock-kind install was the collision). `helm template` without a cluster always sees an empty APIVersions — the fallback is what CI validates by default — `handoff-reported`.
- **NetworkPolicy vs the apiserver (the F5 regression):** policies evaluate post-DNAT (backend port 6443, not the Service's 443), and a `hostNetwork: true` static pod is not selectable by podSelector (empty set under Cilium/Calico) — the podSelector apiserver rule can never carry the fetcher's watch on kubeadm/kind clusters. The portable answers: Cilium's `toEntities: [kube-apiserver]` (CNLP, behind the auto gate) or an ipBlock to the discovered endpoint IPs (`kubectl get endpoints kubernetes`) — `handoff-reported` (Gemini); the rehearsal receipts both live.
- **Cilium ipBlock vs node IPs:** Cilium ignores node IPs in ipBlock rules unless `--policy-cidr-match-mode=nodes` — a cidr-mode apiserver rule under stock Cilium silently drops. The rehearsal installs Cilium with the flag; the README records the caveat — `handoff-reported` (Fable).
- **Policy-change verification must force a FRESH connection** — an established TCP stream can survive a NetworkPolicy change, so "still connected" proves nothing; verify with a fresh API GET (or restart / a new end-to-end delivery) — `handoff-reported` (Fable).
- **Exec readiness probes must speak auth when auth is on:** a headerless POST to a bearer-protected `/mcp` 401s — the probe template reads the mounted token file and sends the header when `server.auth.enabled` — `handoff-reported` (Fable); the 405-on-GET fact is `verified-here` (the 4b record).
- **kindnet enforces NetworkPolicy since kind v0.24** (we pin v0.33) — the "kindnet does not enforce" folklore is wrong; Cilium's case rests on Cozystack parity + CNP coverage — `handoff-reported` (Fable correction of this spec's earlier claim).
- **source-watcher's real pod labels** (flux v2.10.1 bundle): `app: source-watcher`, `app.kubernetes.io/component: source-watcher`, `app.kubernetes.io/instance: flux-system`, `app.kubernetes.io/part-of: flux` — no `app.kubernetes.io/name` label exists. Any policy targeting source-watcher selects `app: source-watcher` (or the component label) — `verified-here`.
- **Flux's shipped policies** (`flux2/manifests/policies/`): `allow-egress` = all flux-system pods, ingress same-namespace only, egress unrestricted; `allow-scraping` = :8080 cross-namespace; `allow-webhooks` = notification-controller :9292. Cross-namespace access to anything else (storage :9090 included) needs an explicit allow — `verified-here`. The :9090 allowance therefore lives in `k8s/repo-sync/` (Fable: every Flux-policies cluster needs it, not just the rehearsal).
- **`flux install --components-extra="source-watcher"`** is the documented install path; `--network-policy` defaults true — `verified-here`.
- **The published server's docs methods had the single-snapshot bug the 4b fix left behind:** `list_docs`/`read_doc`/`search_docs` re-resolved `self.base()` mid-call (`ticket_mcp.py` L355–410); `repo_facts` was the only fully-bind-once method. Rule for future edits: every pod-mode method binds `base` once and threads it through helpers — `verified-here`.
- **The fetcher's `--keep` default is 3** (`k8s/fetcher/main.go`) — the three-commit recipe needs no values override — `verified-here`.
- **kind facts** (docs, 2026-11-25): auto-detects docker/podman/nerdctl; release binaries at `kind.sigs.k8s.io/dl/v0.33.0/…`; `kind load image-archive` takes a saved archive (provider-agnostic with `podman save`); pods reach runner-side servers via the docker/podman network gateway IP — `verified-here`.
- **`fluxcd/pkg/gittestserver`** is Flux's own battle-tested smart-HTTP git test server — the right tool for a runner-side test repo (Fable's suggestion); keep it in a separate module so the fetcher's go.sum stays untouched — `handoff-reported`.
- **Alert eventSources vs the ArtifactGenerator kind:** whether notification-controller v1 matches `kind: ArtifactGenerator` events is verified live in the rehearsal (the sink assertion is optional); if unmatched, `ExternalArtifact` is the working eventSource — the finding lands in the README — `speculation` until the run.
- **`origin_revision`'s exact string** (`main@sha1:<sha>` per the 4b fallback finding) is asserted by substring-containment and recorded verbatim from v2.3.1's live output — assumed prefixes are not asserted — `speculation` until the run, then recorded.
- **A NetworkPolicy only selects pods in its OWN namespace** — a cross-namespace allowance (e.g., admitting the release pods into flux-system) must be applied IN the target namespace or carry `metadata.namespace` explicitly; `kubectl -n <other-ns> apply` lands it in the wrong place and it silently selects nothing (the fetch then times out behind Flux's default-deny — the phase-5 rehearsal's run-#5 receipt). Pin the namespace IN the manifest — `verified-here` + Fable's review.
- **When a connection times out under policies, check BOTH fences (egress AND ingress) and prefer the project's own receipted datapath learnings over a fresh theory:** the post-DNAT (backend-port) evaluation is the settled model here (the F5 apiserver fix's 443/6443) — Service:80→pod:9090 is admitted by a 9090-only egress rule; the run-#5 timeout was the INGRESS side (wrong-namespace policy), not the port — `verified-here` (Fable's review).
- **source-watcher v2.3.1's port shape (the version flux 2.10 installs), receipted from its release manifests:** pod containerPorts http=9090 (storage), http-prom=8080 (metrics), healthz=9440; Service `source-watcher` = 80→http (a flux2 patch adds 443→http); the ExternalArtifact URL carries NO port (`--storage-adv-addr=source-watcher.<ns>.svc.cluster.local.`) — `verified-here`.
- House discipline unchanged: PR to `main`, conventional commits, three labels on every claim, public-safe content only, the box untouched, `mark_task_complete` after the PR merges.

## Implementation notes (2026-11-25, CI incident #2 — all `verified-here` via the public GitHub API)

- **The rehearsal job on `cce9a0c` failed 90s into the script** (jobs API step timing: `run the rehearsal` 22:18:56 → 22:20:26; the annotation is the generic "exit code 1"). Diagnosis without artifact access (downloads are auth-gated): the timing fits `kind create` succeeding (~60s incl. the node-image pull) and **`cilium install` failing fast** — and the smoking gun was in `kind-config.yaml`: **no `networking.disableDefaultCNI: true`**, so kindnetd and Cilium would fight over the datapath (the Cilium-on-kind recipe mandates disabling the default CNI).
- **Interplay gotcha:** once `disableDefaultCNI` is set, the node stays NotReady until Cilium is installed — so `kind create cluster --wait 240s` would **time out and fail the create**. The script now passes `--wait 0s` and polls `kubectl get --raw=/readyz` (120s budget) before Cilium (`0a80195`).
- **Diagnostics channel for credential-less agents (the meta-fix):** GitHub job logs, step summaries and artifact downloads are all sign-in-gated, but **check-run annotations are public-API-readable** — the failure path now emits each log tail as a `::error title=…::` annotation (percent-encoding: `%`→`%25`, newlines→`%0A`, `]`→`%5D`, `;`→`%3B`; tail -c 1400, cut -c 900), over: the full tee'd script output (`exec > >(tee -a …)` catches everything), the git-server log, pods/events dumps, and the controller/pod logs. `kind export logs` also gained its missing `--name`.
- **Sandbox note:** the terminal tool errors with "tool input was not fully received" if the required `cd` parameter is omitted — not a harness outage; always pass `cd`.
- **Next-run watch list:** if Cilium still fails, the annotation tails name the cause — candidates: kind v0.33's default node k8s version vs Cilium v1.18.1 support (fallback: pin `image:` in kind-config to a Cilium-supported node), quay.io pull throttling, or the kind gateway reachability from pods under Cilium.

## Implementation notes (2026-11-25, CI incident #3 — the annotations channel paid off)

- **Run on `0a80195` (annotations readable via the public check-runs API — the channel works):** the cluster came up on kind v0.33's default node (**k8s 1.37.0**) and coredns was even Running with a pod IP — but the script died ~33s into/after `cilium install`, and the error text was invisible because **the annotate helper kept the first 900 bytes of a 1400-byte tail — dropping the END of the log, where the error lives** (fixed: `tail -c 900`, no cut).
- **Second smoking gun, independent of Cilium:** the docker-29 GitHub runner's `kind` network is **dual-stack with IPv6 FIRST in IPAM.Config** — gateway `fc00:f853:ccd:e793::1`, so the test-repo URL rendered as the malformed, unbracketed `http://fc00:f853:ccd:e793::1:38080/repo.git` (not a valid git http URL; the pod path to the runner is the node's IPv4 route anyway). Fixed: select the IPv4 gateway with jq (`.[0].IPAM.Config[] | select(.Gateway | test("^[0-9]+[.]"))`), fail loudly if none.
- **Third fix (prepared from the kind v0.33.0 release notes, fetched):** the default node is k8s 1.37.0, but the pinned Cilium v1.18.1 (Aug 2025) and Flux v2.10.1 are 1.34-era releases — the node image is now pinned explicitly: `kindest/node:v1.34.11@sha256:44e222ee2132dab25ff87301682f89eb82c7880ea3a1bf543bfe9708fd08d67d` (digest straight from the official release notes, which also recommend digest pinning). Newest kind-prebuilt node both pinned components support.
- **Incident #5 (run on `17ebfbb`, `verified-here` via the job-page annotations) — the chain is green THROUGH the ExternalArtifact:** Flux + source-watcher installed ✓, both images built + archive-loaded ✓, the chart installed with defaults ✓ (the fresh-install asserts passed), the test manifests applied ✓, GitRepository **stored the artifact for commit 'fixture seed (T-9001)'** ✓ (the runner-side Smart-HTTP server works end to end), the ArtifactGenerator reconciled `latest@sha256:806ff6…` ✓, the fetcher's **watch saw the ExternalArtifact** (RBAC fine) and tried to fetch — then: `failed to download archive: GET http://source-watcher.flux-system.svc.cluster.local./externalartifact/… giving up after 4 attempt(s): dial tcp 10.96.109.194:80: i/o timeout`.
- **Root cause (Fable's review, verified):** `artifact-ingress.yaml` carried **no `metadata.namespace`** and the rehearsal applied it with `kubectl -n "$NS"` — a NetworkPolicy only selects pods in its OWN namespace, so the policy landed in the release namespace and selected NOTHING, while source-watcher stayed behind Flux's shipped default-deny in flux-system → the fetch SYN is dropped → i/o timeout. **The 9090-only egress rule was NOT the problem**: Service:80 → pod:9090 and Cilium evaluates the BACKEND port — consistent with the project's own F5 apiserver learning (443/6443). The agent's interim pre-translation port theory (which briefly widened the chart rule to ports 80+9090) was WRONG and was reverted in the same push (`a9392a2`) — lesson recorded below.
- **Fix (`a9392a2`):** `artifact-ingress.yaml` pins `namespace: flux-system` under metadata (nobody can repeat the mistake at install time) + the repo-sync README documents the placement and the phase-12 prerequisite (write access in flux-system, or the platform carries the rule); rehearse.sh applies it with `kubectl -n flux-system` (the sed still rewrites the from-selector); the chart is back to the 9090-only egress rule with the URL shape documented in values/README/NOTES. The port-scope probe stays pod-IP-based (:9090 storage allowed / :8080 metrics denied — the Service exposes 80/443 only, so a Service :9090 dial would refuse even policy-free; the pod dial is the meaningful shape). Source receipts: source-watcher v2.3.1 `config/manager/service.yaml` (Service 80→http) + `deployment.yaml` (containerPort http=9090, http-prom=8080, healthz=9440) + flux2 v2.10.1 base patch (adds Service 443→http).
- **Also noted from run #5's events:** one transient `Readiness probe failed` on the release pod (single event; the server probe answered at the fresh-install assert and the pod kept Ready) — watch item, no action unless it recurs.
- **Also aligned with the official Cilium-on-kind recipe** (v1.18 docs, `Documentation/installation/kind.rst`): `--set ipam.mode=kubernetes` added (the docs' helm command for kind; cluster-pool default removed as a variable). The same docs confirm `disableDefaultCNI: true` is the canonical kind config for Cilium.
- **Fix commit `f5d6008`** (node pin + IPv4 gateway + annotate-end + ipam mode). Learnings for future kind-in-CI agents: (1) never trust IPAM.Config[0] for the gateway on docker ≥29 — select the v4 entry; (2) pin the node image to the k8s version the CNI/Flux pins support, not kind's default; (3) keep annotation tails END-anchored.
- **Incident #4 (run on `f5d6008`, `verified-here` via annotations) — the stack is GREEN through Cilium:** kind create on the pinned `kindest/node:v1.34.11` ✓, IPv4 gateway `172.18.0.1` ✓ (the jq selection works), **Cilium v1.18.1 install + status ready on k8s 1.34.11 with `ipam.mode=kubernetes` + `policyCIDRMatchMode=nodes`** ✓ (local-path-provisioner Running with a pod IP — the datapath works). Fixed on `17ebfbb` (flag dropped + a comment so nobody re-adds it). Remaining untested at that point: chart install, the four-commit proof, the cidr upgrade, the denials.
