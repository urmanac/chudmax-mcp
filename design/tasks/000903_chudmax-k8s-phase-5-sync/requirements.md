Everything happens in the public repo `urmanac/chudmax-mcp`: chart fixes the rehearsal's homework surfaced, the one-file server fix (mirrored to the canonical via a private MR, human-merged), the :9090 ingress allowance added to `k8s/repo-sync/`, a `k8s/rehearsal/` directory (config, fixture, test-git-server helper, script, README), and one CI workflow. ## User stories

1. **As the human**, I want the rehearsal to deploy the REAL published server via the chart's default install — not a hand-rolled stand-in — so what CI proves is byte-identical to what `helm install` gives any user.
2. **As the human**, I want the three-commit proof (Fable's, owner-endorsed): commit #1 → the chain delivers hands-off; commit #2 → the server serves the SECOND revision without restarting (the per-call contract under real API load — the regression Fable caught, proven explicitly); commit #3 → retention prunes → the server still answers.
3. **As the human**, I want `repo_facts` asserted between commits: `origin_revision` contains the pushed git SHA (the generator's fallback — the exact string shape recorded from live output, not assumed) and `revision` is the content hash, which CHANGES per commit — all captured on the run.
4. **As the human**, I want the denial proven under Cilium: the fetcher's egress policy — DNS 53, an apiserver rule that actually matches (the `auto`/`cilium` path under the rehearsal's Cilium), artifact server 9090 to source-watcher's pods — is exercised for real; the fetcher still succeeds; a rogue pod outside the policies is denied the artifact URL; and the chart's F4/F5 fixes are validated under a Cozystack-like CNI.
5. **As the human**, I want the reviews' chart/server fixes folded into this phase so the rehearsal runs against a chart that works everywhere: the apiserver egress fix with an `auto` default that survives phase 6's stock-kind install (no Cilium CRDs), the bearer-aware server readinessProbe, the docs-methods bind-once fix in the published server (mirrored to the canonical), the stale mock comment gone, and the :9090 ingress allowance living in `k8s/repo-sync/` where any Flux-policies cluster finds it.
6. **As CI**, I want the rehearsal pinned, repeatable, and loud: fixed tool versions, a cluster created and deleted inside the job, images loaded via archive (no registry), no secrets, receipts on the run — in a workflow file that phase 6's parallel work cannot collide with.

## Acceptance criteria

- [ ] **The real server:** the rehearsal installs the chart with default values — server image built from `k8s/tickets-mcp/Dockerfile`, fetcher from `k8s/image/Dockerfile`, both loaded into kind via archive; no hand-rolled stand-in server exists anywhere in the rehearsal.
- [ ] **The apiserver egress fix (both reviews):**
  - the apiserver rule allows TCP **443 and 6443** in every mode;
  - `apiServer.mode` gains **`auto` as the default**: CiliumNetworkPolicy (`toEntities: [kube-apiserver]`) rendered ONLY when `.Capabilities.APIVersions.Has "cilium.io/v2/CiliumNetworkPolicy"` — otherwise the standard ipBlock fallback (ports 443+6443) so a **stock kind install with chart defaults (phase 6) cannot fail on a missing CRD**;
  - explicit **`cilium`** and **`cidr`** modes kept for `helm template`/CI/overrides; the `podSelector` mode kept with its hostNetwork limitation (empty set under Cilium/Calico) documented;
  - values comment + chart README updated; chart CI green with the CNP render schema-checked (Cilium CRD schema fetched in the validation job) and the fallback render validated plain.
- [ ] **The server readinessProbe (bearer-aware):** an exec probe on the server container POSTing `list_tickets` (or `initialize`) to `127.0.0.1:<server.port>/mcp` asserting HTTP 200 — and when `server.auth.enabled`, the probe reads `/var/run/mcp-auth/token` and sends `Authorization: Bearer <token>` (a headerless POST would 401 and never go ready); the auth-enabled variant is rendered and schema-checked in CI; the probe tolerates the pre-data state (honest answers without a tree) — the fetcher's `test -e current` probe still gates the pod's overall readiness until the first swap.
- [ ] **The published server's bind-once fix:** `list_docs`, `read_doc`, `search_docs` bind `base = self.base()` ONCE at the start and pass it into `readable(base)`; the published selftest gains a regression check for the mid-call-swap hazard (a concurrent swap during docs calls never raises, never falsely refuses); the identical fix goes to the canonical via the private GitLab MR (human merges — the 4b parallel-deliverable pattern; the public PR does not wait on it; a session without provider access flags that honestly); the stale mock comment in `k8s/image/Dockerfile` L2–3 is corrected to the published canonical.
- [ ] **The :9090 ingress allowance lives in `k8s/repo-sync/`** (Fable): `artifact-ingress.yaml` — ingress :9090 to `app: source-watcher` pods from the release namespace's release-labeled pods, no `metadata.namespace` (the repo-sync install convention), the phase-12 note in a comment, covered by the existing repo-sync schema validation; `rehearse.sh` applies it from there; the repo-sync README documents when it is needed (any cluster running Flux's shipped policies).
- [ ] **The Smart-HTTP test repo (no deprecated machinery):** the runner serves the bare repo via a tiny Go helper wrapping Flux's own `fluxcd/pkg/gittestserver` (a separate module under `k8s/rehearsal/` — the fetcher module's dependency set stays untouched; fallback: a Python `BaseHTTPRequestHandler` driving `git-http-backend` via subprocess); the URL is `http://<runner-gateway>:<port>/repo.git` (passes the CRD's `^(http|https|ssh)://` pattern); **the script proves the URL with `git ls-remote` from the runner BEFORE applying the GitRepository**; commit #1 is pushed before the manifests apply and the chain (1m interval → ArtifactGenerator → ExternalArtifact → fetcher swap) delivers v1 with **nobody doing anything** — `list_tickets` over the Service shows the seed ticket; the fresh-install wait → self-heal is observable and asserted on the way.
- [ ] **Commit #2 (the Fable regression, explicit):** pushed; the probe keeps polling `list_tickets` across the swap window; the answer shows v2, every answer after the swap serves the new tree (no stale v1-after-v2), and the server container's `startedAt`/`restartCount` are UNCHANGED — the second revision served without a restart.
- [ ] **Commit #3 (retention):** pushed; the server still answers after the prune (`/data/revisions` ≤ keep=3, v1's dir gone); `repo_facts` captured after EVERY commit and asserted: `origin_revision` **contains** the pushed commit SHA (the exact string — e.g. `main@sha1:<sha>` — recorded from live output, not assumed), `revision` = the content hash and CHANGES between commits; all JSONs land in the CI step summary.
- [ ] **The denials (Cilium-enforced):** the fetcher succeeds with the egress policy ON (positive path under enforcement — the apiserver rule included); a rogue pod (release ns, default ServiceAccount, no labels) GETs the ExternalArtifact via the API → 403 (it cannot even learn the artifact URL — the phase-4 Role answer, now proven) and GETs the artifact tarball from source-watcher:9090 → denied; positive controls: the fetcher's fetch, a label-carrying Role-less pod CAN fetch the tarball (the ingress allowance's shape is what admits), and the port-scope probe from inside the chudmax pod (:9090 allowed, an unlisted port denied) — the fences bite, not merely exist.
- [ ] **The cidr-mode exercise is honest under Cilium (Fable's fix 2):** Cilium is installed with `--policy-cidr-match-mode=nodes` (its default ipBlock handling ignores node IPs otherwise); after the `helm upgrade` to `mode: cidr` with the discovered endpoint IPs (`kubectl get endpoints kubernetes`), the check forces a **FRESH connection** — a fresh in-pod API GET succeeds (an established stream surviving is NOT evidence) — and a **fourth commit** is delivered hands-off end-to-end under the upgraded policy, with no pod restart from the policy-only upgrade; the README documents cidr mode's Cilium caveat (nodes-match-mode, or non-Cilium).
- [ ] **Alerts + the eventSources check:** `alerts.yaml` applied with the Provider pointing at an in-cluster dummy sink; the rehearsal verifies LIVE whether notification-controller matches `kind: ArtifactGenerator` events — if not, `eventSources` gains `ExternalArtifact` and the README records the finding; the delivered-event assertion itself stays optional — dropped honestly if it fights the budget, never left flaky.
- [ ] **CI shape:** `.github/workflows/rehearsal-sync.yml` (pinned kind, flux, Cilium, Go/probe-image refs; `workflow_dispatch` plus path-scoped triggers on `k8s/**`; minimal permissions — nothing is pushed to any remote); the cluster is created and deleted inside the job (cleanup `if: always()`); no secrets; the four existing workflows stay green; **this card edits NO phase-6 file** (`umbrella.yml`, engine-chart/web-chart/umbrella dirs) — a needed helper is duplicated into `k8s/rehearsal/`, not shared.
- [ ] **House rules:** work lands via PR to `main` only; conventional commits; the three labels on all claims; the box untouched; fixture content invented (no real tickets, no LAN hostnames, no tokens); in-sandbox proofs recorded with receipts (CI is the authoritative full-chain proof).
