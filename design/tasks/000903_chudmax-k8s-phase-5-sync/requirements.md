## User stories

1. **As the human**, I want the rehearsal to deploy the REAL published server via the chart's default install — not a hand-rolled stand-in — so what CI proves is byte-identical to what `helm install` gives any user.
2. **As the human**, I want the three-commit proof (Fable's, owner-endorsed): commit #1 → the chain delivers hands-off; commit #2 → the server serves the SECOND revision without restarting (the per-call contract under real API load — the regression Fable caught, proven explicitly); commit #3 → retention prunes → the server still answers.
3. **As the human**, I want `repo_facts` asserted between commits: `origin_revision` contains the pushed git SHA (the generator's fallback — the exact string shape recorded from live output, not assumed) and `revision` is the content hash, which CHANGES per commit — all captured on the run.
4. **As the human**, I want the denial proven under a policy-enforcing CNI (Cilium): the fetcher's egress policy — DNS 53, the apiserver rule in a form that actually matches, artifact server 9090 to source-watcher's pods — is exercised for real; the fetcher still succeeds; a rogue pod outside the policies is denied the artifact URL; and the chart's F4/F5 fixes are validated under a Cilium-like CNI.
5. **As the human**, I want the review's chart/server fixes folded into this phase so the rehearsal runs against a chart that works under Cilium: the apiserver egress fix (ports 443+6443; `cilium` and `cidr` modes; the podSelector mode's limitation documented), a server readinessProbe (architecture.md's list_tickets probe — GET /mcp alone is a 405), the docs-methods bind-once fix in the published server (mirrored to the canonical), and the stale mock comment gone.
6. **As CI**, I want the rehearsal pinned, repeatable, and loud: fixed tool versions, a cluster created and deleted inside the job, images loaded via archive (no registry), no secrets, receipts on the run — in a workflow file that phase 6's parallel work cannot collide with.

## Acceptance criteria

- [ ] **The real server:** the rehearsal installs the chart with default values — server image built from `k8s/tickets-mcp/Dockerfile`, fetcher from `k8s/image/Dockerfile`, both loaded into kind via archive; no hand-rolled stand-in server exists anywhere in the rehearsal.
- [ ] **The chart fixes (the review's showstopper 2 + finding 3):**
  - the apiserver egress rule allows TCP **443 and 6443**;
  - `apiServer.mode` gains `cilium` (renders a `CiliumNetworkPolicy` with `toEntities: [kube-apiserver]` — the **new default**, matching the Cozystack platform; the CNP CRD requirement documented) and `cidr` (an ipBlock list of control-plane endpoint IPs — values-driven, discovered in `rehearse.sh` via `kubectl get endpoints kubernetes`);
  - the `podSelector` mode is kept but documented as unable to match a `hostNetwork: true` apiserver (empty set under Cilium/Calico — legacy, non-hostNetwork platforms only);
  - values comment + chart README updated; existing chart CI stays green, with the CNP render schema-checked (Cilium CRD schema fetched in the validation job).
- [ ] **The server readinessProbe:** an exec probe on the server container POSTing `list_tickets` (or `initialize`) to `127.0.0.1:<server.port>/mcp` and asserting HTTP 200 (GET alone is a 405); it stays tolerant of the pre-data state (the tools answer honestly without a tree) — the fetcher's `test -e current` probe still gates the pod's overall readiness until the first swap; `helm lint`/template/kubeconform green in all variants.
- [ ] **The published server's bind-once fix:** `list_docs`, `read_doc`, `search_docs` bind `base = self.base()` ONCE at the start and pass it into `readable(base)`; the published selftest gains a regression check for the mid-call-swap hazard (a concurrent swap during docs calls never raises, never falsely refuses); the identical fix goes to the canonical via the private GitLab MR (human merges — the 4b parallel-deliverable pattern; the public PR does not wait on it; a session without provider access flags that honestly); the stale mock comment in `k8s/image/Dockerfile` L2–3 is corrected to the published canonical.
- [ ] `k8s/rehearsal/` added with: `kind-config.yaml` (single node), `fixture/` (synthetic tree carrying all four narrowed entries — `tickets.md`, `STATE.md`, `docs/`, `decisions/` — invented content only; the copy rules' `optional: false` must never fire), `gitrepository-test.yaml` (URL `http://<runner-gateway>:<port>/repo.git` rendered by the script, **no** `secretRef` — the deltas vs production documented), `artifact-ingress.yaml` (admission NetworkPolicy: ingress :9090 to `app: source-watcher` pods from the release namespace's release-labeled pods — with the phase-12 note), `rehearse.sh` (the orchestrator), and `README.md` (what is proven, how to run, the findings, the handoff note).
- [ ] **The Smart-HTTP test repo:** the runner serves the bare repo via `git-http-backend` (`GIT_PROJECT_ROOT=/srv/git`, `GIT_HTTP_EXPORT_ALL=1`) behind a Python `CGIHTTPRequestHandler` wrapper; **the script proves the URL with `git ls-remote` from the runner BEFORE applying the GitRepository** (the pre-flight receipt); commit #1 is pushed before the manifests apply and the chain (1m interval → ArtifactGenerator → ExternalArtifact → fetcher swap) delivers v1 with **nobody doing anything** — `list_tickets` over the Service shows the seed ticket; the fresh-install wait → self-heal is observable and asserted on the way.
- [ ] **Commit #2 (the Fable regression, explicit):** pushed; the probe keeps polling `list_tickets` across the swap window; the answer shows v2, every answer after the swap serves the new tree (no stale v1-after-v2), and the server container's `startedAt`/`restartCount` are UNCHANGED — the second revision served without a restart.
- [ ] **Commit #3 (retention):** pushed; the server still answers after the prune (`/data/revisions` ≤ keep=3, v1's dir gone); `repo_facts` captured after EVERY commit and asserted: `origin_revision` **contains** the pushed commit SHA (the exact string — e.g. `main@sha1:<sha>` — is recorded from live output, not assumed), `revision` = the content hash and CHANGES between commits; all three JSONs land in the CI step summary.
- [ ] **The denials (Cilium-enforced):** the fetcher succeeds with the egress policy ON (positive path under enforcement — the apiserver rule included); a rogue pod (release ns, default ServiceAccount, no labels) GETs the ExternalArtifact via the API → 403 (it cannot even learn the artifact URL — the phase-4 Role answer, now proven) and GETs the artifact tarball from source-watcher:9090 → denied; positive controls: the fetcher's fetch, a label-carrying Role-less pod CAN fetch the tarball (the admission policy's shape is what admits), and the port-scope probe from inside the chudmax pod (:9090 allowed, an unlisted port denied) — the fences bite, not merely exist.
- [ ] **The apiserver modes are both live-proven:** the rehearsal installs with the `cilium` mode (default) and then `helm upgrade`s to `mode: cidr` with the script-discovered endpoint IPs — the fetcher keeps working across the upgrade with **no pod restart** (a policy-only upgrade must not touch the pod); the podSelector mode is render-validated only.
- [ ] **Alerts + the eventSources check:** `alerts.yaml` applied with the Provider pointing at an in-cluster dummy sink; the rehearsal verifies LIVE whether notification-controller matches `kind: ArtifactGenerator` events — if not, `eventSources` gains `ExternalArtifact` and the README records the finding; the delivered-event assertion itself stays optional — dropped honestly if it fights the budget, never left flaky.
- [ ] **CI shape:** `.github/workflows/rehearsal-sync.yml` (pinned kind, flux, Cilium, probe-image refs; `workflow_dispatch` plus path-scoped triggers on `k8s/**`; minimal permissions — nothing is pushed to any remote); the cluster is created and deleted inside the job (cleanup `if: always()`); no secrets; the four existing workflows stay green; **this card edits NO phase-6 file** (`umbrella.yml`, engine-chart/web-chart/umbrella dirs) — a needed helper is duplicated into `k8s/rehearsal/`, not shared.
- [ ] **House rules:** work lands via PR to `main` only; conventional commits; the three labels on all claims; the box untouched; fixture content invented (no real tickets, no LAN hostnames, no tokens); in-sandbox proofs recorded with receipts (CI is the authoritative full-chain proof).
