The chudmax-mcp chart is installed. The pod runs the fetcher sidecar; your MCP
server is bring-your-own (disabled by default).

What this install does NOT have yet:

1. The ExternalArtifact. The chart only needs its name
   ({{ .Values.externalArtifact.name }}) — the k8s/repo-sync work creates it
   (phase 4). Until it exists, the fetcher container exits and restarts with
   backoff (its startup read is fatal by design) and self-heals when the
   artifact appears.
2. The image, if you kept the default tag: ghcr.io/urmanac/chudmax/mcp is
   unpublished until the phase-10 milestone. Build/load it yourself meanwhile:

     podman build --platform linux/amd64,linux/arm64 \
       --manifest ghcr.io/urmanac/chudmax/mcp:0.1.0 \
       -f k8s/image/Dockerfile k8s

To attach your own MCP server:

  helm upgrade <release> <chart> --set server.enabled=true \
    --set server.image.repository=<your-image> \
    --set server.image.tag=<tag> \
    --set server.command[0]=<your-server-binary> \
    --set server.args[0]=--root \
    --set server.args[1]={{ .Values.fetcher.root }}/current

Your server reads the volume contract documented in k8s/fetcher/README.md:
revisions/<digest-hex>/ trees, the `current` symlink swapped atomically, and
artifact.json beside every tree — reread through the symlink on every call.

NetworkPolicy caveats: the policies select the POD (both containers); a server
with other egress needs adjusts networkPolicy.egress.extra or disables the
policies. The egress rule for the kube-apiserver must match your cluster's
service CIDR (networkPolicy.egress.apiServer.cidr — kubeadm default shipped).
