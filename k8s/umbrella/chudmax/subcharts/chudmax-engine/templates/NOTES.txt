The ChudMax engine chart — a POINTER, not a workload.

This chart renders no Deployment, no pod, no RBAC: the engine runs where it
runs (the GPU host) and is never containerized. What it renders is the cluster's
stable name for that external engine:

    http://{{ include "chudmax-engine.fullname" . }}:{{ .Values.service.port }}   (a Service without a selector)

{{- if .Values.endpoint.host }}

EndpointSlice: {{ include "chudmax-engine.fullname" . }}-endpoints → {{ .Values.endpoint.host }}:{{ .Values.endpoint.port }}

{{- else }}

*** endpoint.host is EMPTY — the Service currently has NO endpoints. ***

Set this to your engine's address at install time, e.g.:

    helm upgrade <release> {{ .Chart.Name }} \
      --set engine.endpoint.host=<your-engine-host> \
      --set engine.endpoint.port=<the engine's port>

(The EndpointSlice renders only once the host is set; the port is the engine's
own and stays decoupled from the client-facing Service port.)

{{- end }}

First test of any cluster — a pod reaching /health through this Service:

    helm test <release>

The same hook rehearses the mock engine on kind and, at phase 11, the real
engine on the platform. The address is values-driven: public artifacts carry
only RFC 5737 documentation IPs, never a real LAN address.
